# «Мои расходы» — описание проекта

## Одной фразой

Личный дневник трат: вносишь расходы, видишь, куда уходят деньги, следишь за лимитами.
Всё работает в браузере, без регистрации и без сервера.

## Зачем это нужно пользователю

Человек не помнит, на что ушла зарплата. Приложение отвечает на три вопроса:
«сколько я потратил в этом месяце», «на что именно» и «не вышел ли я за рамки бюджета».

## Что на экране

1. **Сводка за месяц** — крупная сумма, листание месяцев стрелками, прогноз трат до конца месяца
   по текущему темпу, круговая диаграмма по категориям с процентами.
2. **График по месяцам** — последние 6 месяцев столбиками. Клик по столбику открывает этот месяц.
3. **Форма «Новая трата»** — сумма, категория, дата, комментарий. Неверную сумму не пропускает.
4. **Список трат** — фильтр по категории, редактирование по кнопке ✎, удаление с возможностью отменить.
5. **Лимиты** — общий на месяц и отдельный на каждую категорию. Полоска зеленеет, желтеет
   и краснеет по мере приближения к пределу; при превышении пишется, на сколько именно.

## Следующие шаги

1. Экспорт в CSV.
2. Импорт выписки из банка (отдельный сложный этап: кодировки, разные форматы).
3. Тёмная тема.
4. Повторяющиеся траты (подписки, аренда).
5. Синхронизация между устройствами — только если появится сервер.

## Технические решения, о которых стоит помнить

- **Суммы хранятся в копейках целыми числами.** Дробные числа в JavaScript дают ошибки
  округления: `0.1 + 0.2 = 0.30000000000000004`. Для денег это недопустимо.
- **Данные в localStorage**, а не на сервере. Плюс: нет затрат, нет утечек, работает офлайн.
  Минус: у каждого устройства своя история — об этом честно написано в шапке.
- **Один источник правды** — массив `expenses` в `App.tsx`. Сводка, графики и список не хранят
  свои копии, а считаются из него. Поэтому цифры не могут разойтись.
- **Расчёты вынесены из компонентов** в `src/lib` и покрыты тестами. Компоненты только показывают.
- **Диалог — это «родной» `<dialog>`**. Браузер сам затемняет фон, ловит Esc и удерживает фокус.
- **Диаграммы нарисованы на SVG вручную.** Это снимает 100+ КБ зависимости и показывает,
  что автор понимает геометрию, а не только умеет подключать библиотеки.

## Что говорить на собеседовании

1. «Почему без бэкенда?» — инструмент личный, данные чувствительные, сервер здесь добавляет
   риск и стоимость, но не пользу. Если понадобится синхронизация — появится API и авторизация.
2. «Почему суммы в копейках?» — история про точность вычислений с плавающей точкой.
3. «Как устроено состояние?» — один массив данных + производные вычисления; черновики форм
   живут отдельно и не попадают в сохранённые данные.
4. «Что было самым сложным?» — лимиты: нужно было разделить «что человек печатает» и
   «что уже сохранено», иначе лимит терялся при уходе из поля.
5. «Как проверяли?» — 22 юнит-теста на чистые функции; тесты нашли реальную ошибку:
   прогноз считался по всем тратам, а не только по выбранному месяцу.
